# Routebase

> Routebase keeps your docs, mocks, and tests in sync with your API. Those copies drift apart as soon as the API changes, because each of them holds its own version of the contract. One living OpenAPI specification is the single source of truth instead, so you change it once and the docs, mock servers, tests, and monitors follow in a single publish. Routebase writes that specification for you if your API doesn't have one. Its testing replaces Postman collections outright with declarative test suites, chained scenarios, data-driven runs, OWASP API Top 10 scanning, and a CLI that gates CI, with or without a spec. Every workspace ships a built-in MCP (Model Context Protocol) server that covers the full feature set, so AI agents work the same spec as your team under the same permissions.

The platform covers five lifecycle stages: Design (visual OpenAPI editor with spec branches and merge requests), Mock (spec-driven mock servers with realistic data), Test (suites, assertions, OWASP security scanning), Document (published docs portals), and Agents (MCP server).

An existing OpenAPI file is not a prerequisite. Start from an empty specification and add endpoints in the visual editor, from a CRUD or auth template, or from a Postman or Insomnia collection — Routebase builds the OpenAPI as you go. Testing works with no specification at all: a test case is a plain HTTP request, and linking it to a designed endpoint is optional and only needed for contract testing.

## What Routebase is

- An API testing tool: test cases are plain HTTP requests with one of ten auth schemes; assertions are declarative (6 types × 10 operators, no test scripts to maintain); cases chain into scenarios that pass extracted values downstream; suites run once per row of a data set, on a cron schedule, or in CI via the CLI and GitHub Action with exit codes. Postman and Insomnia collections import directly. No OpenAPI spec is required.
- An API security scanner: OWASP API Top 10 scanning with 13 scanners, multi-identity personas, finding triage, and a CI gate.
- An API design tool: a visual OpenAPI 3.0/3.1 editor with JSON Schema builder, spec branches with merge requests, and 53+ governance lint rules.
- A mock server: spec-driven mocks with realistic data, stateful behaviour, latency and failure simulation.
- An API documentation portal: branded, on your own domain, with try-it console, search, versioning, and llms.txt output.
- An API monitor: uptime and check monitoring with alert policies, plus contract drift detection between spec and production.
- An MCP server: it covers the full feature set, so AI agents design, test, and document under your workspace's permissions.
